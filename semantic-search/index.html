Semantic Search in Contentbase

keyword + vector + hybrid search for your markdown collections

Contentbase now ships with a full semantic search engine powered by bun:sqlite, FTS5, and OpenAI embeddings. Search your document collections via CLI, REST API, MCP tools, or the TypeScript API — with keyword, vector, or hybrid modes.

2 — Getting Started

Before you can search, you need to build a search index from your contentbase collection. This extracts document sections, generates embeddings, and stores everything in a local SQLite database.

1

Build the search index

Run from your project root (where docs/models.ts lives). Uses OpenAI embeddings by default — requires OPENAI_API_KEY in your environment.

cbase embed

This creates .contentbase/search.sqlite at your project root with all documents indexed.

2

Check index health

Verify the index is built and see statistics about what's indexed.

cbase embed --status

Reports document count, chunk count, embedding count, provider, model, dimensions, and database size.

3

Search!

Now query your documents with natural language.

cbase search "authentication flow"
Local embeddings (optional): Don't want to use OpenAI? Run cbase embed --local to auto-install node-llama-cpp and generate embeddings locally. This adds a native dependency but keeps everything offline. Use cbase embed --install-local to install without indexing.
3 — Three Search Modes

Every search surface supports three modes. Choose based on your query type, or use hybrid (the default) for best overall results.

Keyword
BM25 via FTS5
Traditional full-text search using SQLite's FTS5 extension. Matches exact terms and stems with BM25 ranking.
Best for
Exact terms, filenames, error messages, specific identifiers you know exist in the docs.
Vector
Cosine similarity on embeddings
Converts your query to a vector embedding, then finds the most semantically similar document chunks via cosine similarity.
Best for
Conceptual queries, "how does X work?", finding related content even without matching words.
Hybrid
Recommended
Reciprocal Rank Fusion (RRF)
Runs both keyword and vector search in parallel, then fuses results using RRF scoring. Gets the best of both worlds.
Best for
General-purpose searching. The default mode — handles both precise terms and fuzzy concepts well.
4 — CLI Usage

Searching

# Hybrid search (default mode)
cbase search "authentication flow"

# Keyword-only search, filtered to Story model
cbase search "user login" --mode keyword --model Story

# Vector search, 20 results, JSON output
cbase search "security best practices" --mode vector -n 20 --json

# Search with metadata filter
cbase search "deployment" --where "status=approved,priority=high"

# Bootstrap: build index if missing, then search
cbase search "api design" --bootstrap

Embedding / Index Management

# Build index (incremental — skips unchanged docs)
cbase embed

# Force full rebuild (clears and re-indexes everything)
cbase embed --force

# Check index status
cbase embed --status

# Use local embeddings instead of OpenAI
cbase embed --local

# Install local embedding dependencies only
cbase embed --install-local
Incremental indexing: By default, cbase embed uses content hashing to skip documents that haven't changed. Only new or modified documents get re-embedded, making subsequent runs fast. Use --force to bypass this.
5 — REST API

The REST API is served by cbase serve. All search endpoints support both GET (query params) and POST (JSON body).

Method Endpoint Description Parameters
GET POST /api/search Main search endpoint q, mode, model, limit, where
GET POST /api/semantic-search Semantic search variant q, mode, model, limit, where
GET /api/search/status Index health & statistics —
POST /api/search/reindex Trigger index rebuild pathIds?, force?

Search Request

# GET
curl "localhost:3000/api/search?q=auth&mode=hybrid&limit=5"

# POST
curl -X POST localhost:3000/api/search \
  -H "Content-Type: application/json" \
  -d '{
    "query": "authentication flow",
    "mode": "hybrid",
    "model": "Story",
    "limit": 10,
    "where": { "status": "approved" }
  }'

Search Response

[
  {
    "pathId": "stories/user-login",
    "model": "Story",
    "title": "User Login Flow",
    "score": 0.847,
    "snippet": "Users authenticate via...",
    "matchedSection": "Authentication",
    "headingPath": "## Authentication",
    "meta": { "status": "approved" }
  }
]
Reindex endpoint details 
# Reindex specific documents
curl -X POST localhost:3000/api/search/reindex \
  -H "Content-Type: application/json" \
  -d '{ "pathIds": ["stories/login", "epics/auth"] }'

# Force full rebuild
curl -X POST localhost:3000/api/search/reindex \
  -H "Content-Type: application/json" \
  -d '{ "force": true }'
6 — MCP Tools

The contentbase MCP server exposes three search tools to Claude and other MCP clients. Start with cbase mcp.

keyword_search
keyword_search({
  query: "user registration",
  limit: 10,
  model: "Story"
})

BM25 keyword search using FTS5. Fast, precise term matching.

semantic_search
semantic_search({
  query: "how does auth work",
  limit: 10,
  model: "Epic"
})

Vector similarity search. Finds semantically related content.

hybrid_search
hybrid_search({
  query: "security validation",
  limit: 10,
  model: "Task",
  where: { status: "approved" }
})

Combined keyword + vector with RRF fusion. Best overall results.

Vector Storage
  • Embeddings stored as Float32Array blobs
  • Cosine similarity computed in JavaScript
  • OpenAI: 1536 dims (text-embedding-3-small)
  • Local: 768 dims (llama model)
  • No native vector extensions needed
Hybrid RRF Scoring
  • Runs keyword + vector search in parallel
  • Fuses via Reciprocal Rank Fusion
  • Formula: score = 1 / (k + rank + 1)
  • RRF constant k = 60
  • Deduplicates by pathId (keeps best score)
Document chunking details

Documents are split into chunks based on H2 headings (##). Each chunk preserves:

  • heading — the H2 heading text
  • text — all content under that heading until the next H2
  • pathId — back-reference to the source document

Content before the first H2 becomes its own chunk with heading null. The entire document also gets a row in documents_fts for full-document keyword search.

Incremental indexing via content hashing

Each document's content is hashed (SHA-256 of title + content + meta). On re-index:

  • If the hash matches the stored hash → skip (no re-embedding needed)
  • If the hash differs → delete old chunks, re-embed, store new chunks
  • If a pathId no longer exists in the collection → remove stale document and chunks

This makes cbase embed safe to run repeatedly. Only changed documents cost API calls.

8 — ContentDb TypeScript API

Use the ContentDb feature directly in your TypeScript code for programmatic access to search. 

// Access ContentDb via the container
const docs = container.docs
if (!docs.isLoaded) await docs.load()

// Build the search index (incremental by default)
await docs.buildSearchIndex({
  onProgress: (indexed, total) => console.log(`${indexed}/${total}`)
})

// Force full rebuild
await docs.rebuildSearchIndex()

// Search — all three modes available
const results = await docs.hybridSearch("authentication flow", {
  limit: 10,
  model: "Story",
  where: { status: "approved" }
})

// Keyword-only
const keywordResults = await docs.search("login endpoint")

// Vector-only
const vectorResults = await docs.vectorSearch("how does auth work")

// Check index health
const status = docs.searchIndexStatus
console.log(status)
// { exists: true, documentCount: 47, chunkCount: 183, ... }
Result shape: Each result includes pathId, model, title, score, snippet, matchedSection, headingPath, and meta. Use pathId to load the full document via collection.document(pathId).
Direct SemanticSearch feature usage

For lower-level control, use the SemanticSearch feature directly:

import { SemanticSearch } from '@soederpop/luca/agi'

const ss = new SemanticSearch(container, {
  dbPath: '.contentbase/search.sqlite',
  provider: 'openai',  // or 'local'
})

await ss.initDb()
await ss.indexDocuments(documentInputs)

const results = await ss.hybridSearch("query", { limit: 10 })
const stats = ss.getStats()
